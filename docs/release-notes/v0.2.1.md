## What's fixed

A maintenance release. No new features — this is the result of an audit of the
whole codebase, and most of what it found had been failing quietly.

### The diagnostics window works

Its Close button and `Esc` did nothing, because the window had never been
granted permission to close itself and the failure was swallowed. Closing it
from the title bar destroyed it instead of hiding it, so the tray's
**Diagnostics…** item worked exactly once per run and then went dead. On macOS
it was also pinned to whichever desktop the app had launched on, so opening it
from another Space looked like nothing happened.

This is the window that opens by itself when the keyboard hook fails on a first
run — the moment it was least able to help.

### Triggers come back when Windows drops the keyboard hook

Windows detaches a keyboard hook that takes too long to answer, and it does not
say so. Prompt Player kept reporting the hook as healthy: the tray showed
armed, diagnostics showed listening, and every trigger silently did nothing
until you restarted the app. It now notices and reinstalls the hook.

### macOS: triggers could stop matching until restart

A timing window let a second keyboard tap install itself while the first was
recovering. With two taps running, every keystroke was seen twice, so `build`
arrived as `bbuuiilldd` and nothing matched again for the rest of the session.

### The Windows tray menu caught up

Three things the macOS menu had and the Windows one did not:

- **Install update / Skip this version.** On Windows an available update never
  appeared in the tray at all; the About window was the only place it showed.
- **Stop Typing**, while a prompt is playing. The only way to abort was the
  keyboard shortcut, which is a poor thing to go looking for mid-demo.
- **Keep Awake for…**, with the auto-off durations. On Windows there was no way
  to change the duration from anywhere in the UI.

### A warning when the palette might be visible

The palette is hidden from screen capture, but on some Windows 11 machines the
OS can only manage a weaker mode that paints a black rectangle where the
palette sits — visible to whoever you are sharing with. That fell back silently
and said so only in a log file. The tray icon now carries a badge, both tray
menus show a row, and diagnostics reports it.

### Quieter when idle

Two background refresh loops ran every two seconds from launch until quit,
whether or not you had ever opened the windows they belonged to. One of them
re-serialised your entire prompt library each time. Both are event-driven now,
so an idle Prompt Player sitting in the menu bar does close to nothing.

### Your prompts survive a crash mid-save

Prompt files, settings and `promptplayer.yaml` were written in place, which
leaves a half-written file if the app is killed or the disk fills at the wrong
moment — and for a prompt, the file watcher would then load that truncation
over the good copy in memory. They are now written completely and swapped into
place.

### Prompts fire sooner

Scope patterns were recompiled on every fire, and a prompt with several
`${{ … }}` expressions built a fresh JavaScript engine for each one. Both sat
in the gap between typing `trigger>` and the first character appearing.

### Safer handling of prompt files and helpers

- Importing a `.pp.md` can no longer write outside your prompts folder,
  whatever the file's own metadata claims its name is.
- Saving a prompt writes inside the library, and nowhere else.
- The `git()` expression helper is read-only for real: it previously accepted
  flags that write a file, which is not what a read-only helper should be able
  to do. It also no longer hangs a prompt when the repository is slow — it
  gives up after five seconds instead of waiting indefinitely.
- Your clipboard is read only when a prompt actually uses `$CLIPBOARD` or the
  `clipboard` expression. A prompt whose text merely mentioned the word was
  enough before.

### Smaller fixes

- Per-prompt hotkeys no longer unregister and re-register every time you save
  an unrelated prompt.
- A symlink loop inside the prompts folder no longer crashes the app at startup
  and on every reload.
- The RDP guide no longer points at a guest-helper installer that is not built
  and that nothing connects to, and it names the config key that actually
  changes the recognised client list.

### Upgrading

Existing installs pick this up through the built-in updater. Your prompts,
triggers and hotkeys are unchanged.
